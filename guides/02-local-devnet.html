Every piece, what it is, which command creates it, and what disappears when you close the terminal. Written so you can do the whole thing from scratch on your own.

4 commands · ~5 min to run · Nothing costs money

A "local blockchain" is just an ordinary program running on your laptop that pretends to be Ethereum. It listens on localhost:8545, holds a big table of accounts and contract data in memory, and executes any transaction you send it — instantly, for free, with no connection to the real world. Everything below is you loading Livepeer's contracts into that program and then poking at them. Kill the program and all of it evaporates.

PIECE 01 — THE FAKE CHAIN

One process, one port, 250 imaginary millionaires.

When you run npx hardhat node, nothing mysterious happens. A Node.js program starts, opens an HTTP server on port 8545, and begins speaking a protocol called JSON-RPC — the same language a real Ethereum node speaks. Anything that knows how to talk to Ethereum (a script, a wallet, a block explorer) can point at http://127.0.0.1:8545 and will not be able to tell the difference.

Inside, it's holding a database: which addresses exist, how much ETH each one has, what code is deployed where, and what data each contract has stored. That database starts empty except for 250 pre-funded test accounts, each with 10,000 fake ETH. Their private keys are printed in the startup log and are identical on every developer's machine on earth — which is exactly why you must never send real money to them.

Two properties make it a development tool rather than a simulation of reality. It mines instantly: a real Ethereum transaction waits for the next block, but here every transaction is confirmed the moment you send it. And it is entirely in memory: there is no database file, no chain history on disk. Ctrl-C and the whole world is gone.

PIECE 02 — THE FOUR COMMANDS

Each command does exactly one thing. Here's which.

The confusing part isn't any single command — it's that four separate things must happen in order, in two different terminals, and only the first one is obvious. Here is the whole sequence with what each step actually changes.

TERMINAL 1leave this running

Start the fake chain.

Creates the empty world from Piece 01. It prints 250 accounts and then sits there. This terminal is now occupied — every other command goes in a second terminal.

npx hardhat node --no-deploy
TERMINAL 2~13 seconds

Deploy Livepeer onto it.

Compiles the Solidity if needed, then sends about 21 transactions that upload each contract's code into the chain and wire them together. This is the step that turns a blank Ethereum into a Livepeer.

yarn deploy --network localhost
TERMINAL 2easy to miss

Add the one contract the deploy script forgets.

Deploys a stub for L2LPTDataCache. On the real network this reports how much LPT is circulating on Ethereum; locally nothing provides it, and without the stub the Minter calls an empty address and everything reverts.

npx hardhat deploy --tags ARBITRUM_LPT_DUMMIES --network localhost
TERMINAL 2flips one boolean

Turn the protocol on.

Livepeer deploys in a paused state on purpose — a safety mechanism so a real deployment can be inspected before anyone can use it. Locally it just means nothing works until you flip it.

npx hardhat unpause --network localhost

After those four, the protocol is live on your machine and you interact with it by running scripts against it: npx hardhat run --network localhost scripts/whatever.ts, or npx hardhat console --network localhost for an interactive prompt.

FIG. 02 — WHICH COMMAND TOUCHES WHAT

Notice the asymmetry in that diagram, because it's the thing that trips people up on day two: the chain is memory, the address book is disk. The folder deployments/localhost/ holds a JSON file per contract recording where it was deployed. Your scripts read it to find addresses. But if you restart the node without re-deploying, those files describe a world that no longer exists — every address in them now points at nothing. When in doubt, delete the folder and redo steps 2 through 4.

PIECE 03 — WHAT LANDS ON THE CHAIN

Twenty-one contracts, but only six you'll ever talk to.

Step 2 deploys a lot. Most of it you can ignore for months. The map below separates the handful you'll actually call from the scaffolding that exists to hold them together.

The pattern to recognize: most contracts arrive in pairs. BondingManagerTarget holds the logic; BondingManager is the permanent address that forwards calls to it. You always use the short name. The Target half is only interesting when you're practicing upgrades.

FIG. 03 — YOUR LOCAL DEPLOYMENT, GROUPED

Two of those deserve a second look because they exist only because you're local, and they're what make experimentation possible at all:

TIME MACHINE

AdjustableRoundsManager

On mainnet a round is 5,760 Ethereum L1 blocks — roughly 19–20 hours — and you wait. This local version lets you call mineBlocks(n) to jump forward instantly. A year of protocol history takes seconds.

FREE MONEY

LivepeerTokenFaucet

Holds 6,343,700 fake LPT, and your deployer account gets another 500,000 minted directly. On mainnet you'd have to buy LPT; here you hand it out to as many test accounts as you like.

PIECE 04 — RUN IT YOURSELF

From a fresh clone to minted rewards, unassisted.

One-time setup, in the repo root. The .env file must exist but can stay completely empty for local work — its keys are only for talking to real networks.

cd ~/Documents/code/protocol
cp .env.sample .env
yarn                # installs dependencies, a few minutes
yarn compile        # downloads solc 0.8.9, ~1 minute

Then the four commands. Terminal 1:

npx hardhat node --no-deploy

Terminal 2:

yarn deploy --network localhost
npx hardhat deploy --tags ARBITRUM_LPT_DUMMIES --network localhost
npx hardhat unpause --network localhost

You should see Controller 0x5FbDB2315678afecb367f032d93F642f64180aa3 paused=false. That address will be identical on your machine and everyone else's, because a fresh local chain is deterministic.

Now create scripts/drive.ts — it has to live inside the repo or the hardhat import won't resolve — and run it with npx hardhat run --network localhost scripts/drive.ts:

import {ethers, deployments} from "hardhat"

async function main() {
    const [me] = await ethers.getSigners()
    const at = async (n: string, as = n) =>
        ethers.getContractAt(as, (await deployments.get(n)).address)

    const bm = await at("BondingManager")
    const rm = await at("AdjustableRoundsManager")
    const token = await at("LivepeerToken")

    // get the clock off block zero, then open the first round
    const roundLength = await rm.roundLength()
    await (await rm.mineBlocks(roundLength.mul(1000))).wait()
    await (await rm.initializeRound()).wait()

    // become an orchestrator
    const amount = ethers.utils.parseEther("1000")
    await (await token.approve(bm.address, amount)).wait()
    await (await bm.bond(amount, me.address)).wait()
    await (await bm.transcoder(100000, 500000)).wait()

    // you only join the active set from the NEXT round
    await (await rm.mineBlocks(roundLength)).wait()
    await (await rm.initializeRound()).wait()

    const before = await bm.transcoderTotalStake(me.address)
    await (await bm.reward()).wait()
    const after = await bm.transcoderTotalStake(me.address)
    console.log("minted:", ethers.utils.formatEther(after.sub(before)))
}

main().catch(e => { console.error(e); process.exit(1) })

Expected output: minted: 0.9786491. You just staked, waited a day, and collected inflation.

When it breaks

HH604: No deployment found for: Controller — you forgot --no-deploy on the node command. Hardhat tried to auto-run the deploy scripts at startup and one of them assumes a Controller already exists.

function call to a non-contract account — you skipped step 3. The Minter is calling L2LPTDataCache, which isn't there.

system is paused — you skipped step 4.

Arithmetic underflow on initializeRound() — you didn't mineBlocks() first. The chain starts at block zero and the contract tries to read the previous block's hash.

Everything reverts for no reason after a restart — deployments/localhost/ is stale. rm -rf deployments/localhost and redo steps 2 through 4.

PIECE 05 — WHAT YOU CAN DO WITH IT

You own every account, so you can play all the roles at once.

This is the part worth internalizing: on your local chain you control all 250 accounts. You can be the orchestrator, five competing orchestrators, a dozen delegators, and the gateway paying them — simultaneously, in one script. No coordination, no permission, no waiting.

You can…By…
Fast-forward a year of protocol historyLooping mineBlocks(roundLength) + initializeRound() + reward() 365 times. Takes seconds.
See how commission affects delegator returnsRunning the same scenario with different rewardCut values and comparing pendingStake(). This is a real economic experiment.
Watch the active set fight for positionRegistering 15 orchestrators when only 10 slots exist, then bonding more stake to one and seeing who gets evicted.
Run the payment lotteryFunding a deposit and reserve, signing tickets, and redeeming a winner. test/helpers/ticket.js has the signing code.
Practice a protocol upgradeDeploying a modified BondingManagerTarget and re-pointing the Controller at it, then checking that all stake survived.
Run a governance vote end to endProposing through LivepeerGovernor, voting with staked LPT, and having a delegator override their orchestrator's vote.
Break things on purposeTrying to withdraw before the unbonding period, reward twice in a round, or bond zero. Reading the revert messages teaches the rules faster than reading the code.
Answer the memo's economics questionsScripting a scenario, dumping the numbers to CSV, and charting them. This is the seed of the simulation track.

What you can't do locally

Actually transcode video. Nothing here touches video — that's go-livepeer, a separate Go program that runs the GPU work and talks to these contracts. Locally you're simulating the money and coordination, with the work itself assumed. Guide 04 breaks down exactly which of its jobs your buttons replaced.

See real network conditions. Your chain has no other users, no competition for block space, no gas price pressure, and no adversaries. Fees are free and instant, which is exactly what makes it useless for judging what a change costs in practice.

Test against real state. Your Livepeer starts empty. The real one has years of accumulated stake, delegations and pending earnings. That gap is what forking addresses — copying live mainnet state into a local chain and experimenting against that instead. Your local chain is the sandbox; a fork is the dress rehearsal.

"Locally you can do anything and it means nothing. That's the trade, and for learning it's the right one."

Quick reference.

Local chain / devnet
A program on your laptop pretending to be Ethereum. Instant, free, in-memory, connected to nothing.
Hardhat
The tool that runs the fake chain, compiles Solidity, and executes your scripts. Every command here starts with it.
localhost:8545
The port the fake chain listens on. --network localhost means "send this there."
Transaction (tx)
A function call sent to a contract that changes stored data. Costs gas on a real chain; free here.
Deploy
Uploading a contract's compiled code into the chain so it has an address and can be called.
Revert
A failed transaction. All its changes are undone and you get an error message. Reverts are normal and informative.
deployments/localhost/
JSON files on disk recording where each contract landed. Survives restarts — which is the problem, because the chain doesn't.
artifacts/ · typechain/
Compiler output and generated TypeScript types. Regenerated by yarn compile; safe to delete.
Proxy vs Target
BondingManager is the permanent address you call; BondingManagerTarget is the swappable logic behind it.
Fork
A local chain seeded with a copy of real mainnet state. Between a blank devnet and the real thing.
